## Repeated attempts, author-approved 3 November 2026

A completed ID may start the task again using **Start another attempt** on the completion page. The participant ID and source remain the same. Each additional attempt receives a random attempt identifier in its URL and a separate session file. Refreshing an unfinished attempt resumes that attempt. The original study URL still restores the original session and offers the repeat button once it is complete. Earlier responses are never deleted or overwritten to permit a repeat.

New records include `participant_session_id` (the stable original-session identifier), `attempt_id` (`original` or the random token), and `repeat_attempt`. These fields are additive; older records without them remain valid. Extraction must group by participant ID/linkage hash and round, rather than count session files as unique participants, and apply the author's duplicate/test filtering rule. The application does not automatically exclude repeat attempts. An app repeat does not reset Prolific's own submission status.
